## Problem Statement

Context: PR #2 (release 0.2.0) is reviewed and its three debt items (an allowlist value of `","`
bypassing the fail-closed budget guard, a dead extension-marker loop in `triage-pr.sh`, and a
run-together header sentence) are declared owners for this release. This design is for 0.3.0 and
is written on the 0.2.0 branch only because PR #2 is not merged yet.

The owner asked for the shell scripts, Python scripts and gate workflow to be audited and aligned
with ISO 27001 (A.8.28 secure coding, A.8.32 change management) and ISO 42001 (traceability and
lifecycle governance). The request text was written for an older design: GitHub Actions ran the
review, a 300-second wait polled PR comments, and the fixer ran inside a workflow. That design is
gone. The skills are in `.agents/skills/`, review and fix run as sub-agents of the person's own
harness session, no workflow calls a model, and a PR comment never grants cycles.

So the task is to carry each of the four items (A to D) over to the current design and fix what
is actually wrong, not to rebuild what the text assumed.

## What Makes This Cool

The loop can show an auditor, for any merged change, which commit was reviewed, with what counts,
who published the verdict and when, and which model and tier the publishing session reported,
without any key or service outside GitHub. Model and tier are self-attested by that session and
are not verified; only the commit, counts, publisher and timestamps come from the PR itself.

## Constraints

- No provider API key anywhere. Review and fix are sub-agents of the person's session.
- The reviewer is read-only on the working tree, so `publish` cannot write into the repository.
- A script cannot sandbox the agent's own tool calls; isolation of test execution belongs to the
  harness.
- Markers are published under the person's own GitHub login, so the gate checks that a trusted
  account published a verdict, not that a different account did.
- Everything in the project is written in English. The shared files exist in both skill folders
  and must stay byte-identical.

## Premises

1. Task D is verified against the current design, not reintroduced. After 5 cycles `budget` says
   `ask`, no cycle starts, `stop` or no answer runs `halt`, the PR stays `review:blocked` with
   `review:needs-human`, and the gate fails there. There is no 300-second wait and no PR-comment
   grant.
2. Task A, revised after the second opinion: a marker counts only if its author is in
   `REVIEW_MARKER_AUTHORS` and the comment was not edited after creation. `gh pr view --json
   comments` has no `lastEditedAt`; it is GraphQL-only (`IssueComment.lastEditedAt`), so the check
   needs a GraphQL call. `status`, the gate and `budget` all fail closed with an empty allowlist,
   including a value that parses to no login such as `","`.
3. Task B: there is no test engine to sandbox. The mechanical barrier is before any write:
   `review-cycle.sh fix` refuses a PR from a fork, or when the PR author or any commit author on the
   branch is not a collaborator with write access or higher (resolved as in step 3 of the order
   of work). Test isolation comes from the harness's sandbox and is
   documented, not simulated.
4. Task C: the reviewer does not write into the repository. The evidence goes into the verdict
   marker (model id and tier added as optional fields) and a per-machine JSONL kept only as a
   convenience copy. Exporting into `docs/compliance-records/` is an explicit human step through a
   pull request. Model id and tier are self-attested by the publishing session; nothing in this
   release verifies them.

Signing the marker was proposed by the second opinion and deferred to the backlog by the owner.

## Cross-Model Perspective

Independent cold read (Claude sub-agent, fresh context):

- Strongest version: sign the marker (`ssh-keygen -Y sign`) and verify it in the gate against an
  `allowed_signers` file on the base branch. That replaces the login allowlist and the edit check
  and binds model id, tier and counts cryptographically. A hash of the previous marker would
  expose deleted or reordered passes.
- Weakest premise: premise 4. An unsigned per-machine log is not audit evidence for A.8.32; its
  gaps and rewrites are undetectable and it dies with the laptop. Premise 2 also had a defect:
  `lastEditedAt` is not in `gh pr view` JSON. Verified in this session: the fields are `author,
  authorAssociation, body, createdAt, id, includesCreatedEdit, ...`, and GraphQL returns
  `lastEditedAt`.
- Existing tooling: rulesets with required signed commits, the PR timeline as an immutable event
  record, the harness's own sandbox for B.
- Fix it first: `status` and `budget` treat `","` as an active allowlist while the gate fails
  closed on it.

Disagreement kept on record: signing adds key distribution and breaks publishing from a second
machine, which is a real operating cost for a one-person project. The owner chose to fix the
verifiable defects now and keep signing in the backlog until an auditor needs it.

## Approaches Considered

### Approach A: Minimal
Only the verifiable corrections and the proof for Task D: fail closed on an empty or login-less
allowlist in `status`, the gate and `budget`; `lastEditedAt` through GraphQL; `fix` refuses forks
and branches with a non-collaborator PR or commit author; tests for the circuit breaker. Effort S, risk low. Leaves Task C unmet.

### Approach B: Complete without signing (chosen)
A plus `publish --model <id> --tier fast|standard|deep` writing optional fields into the marker
and the report, and `review-cycle.sh export-audit <pr>` that builds
`docs/compliance-records/<pr>-<pass>.json` from the PR's own timeline (labeled events with actor
and time, comments, head sha) and the marker fields, for a human to commit through a pull request.
Effort M, risk medium (marker format change, optional fields).

### Approach C: Lateral, timeline only
No marker change and no local log; the PR timeline is the only record. Model id and tier have
nowhere to live, so Task C is half met. Its idea of using the timeline as the export source is
folded into B.

## Recommended Approach

Approach B. It meets Task C with fields a reader can read and compare against the PR's own
timeline (model id and tier stay self-attested), keeps the format change backward
compatible (readers that do not know the fields ignore them, as with the count group), and uses
GitHub's own timeline as the export source so the local JSONL is never the evidence.

Order of work:
1. Fail-closed allowlist in `status`, the gate and `budget`, plus the `","` test.
2. `lastEditedAt` through GraphQL in `review-cycle.sh` `parse()` and the gate. The query pages
   through all issue comments and fails closed when a page is truncated or the call fails. Tests:
   an edited marker is ignored, and a truncated page fails closed.
3. `fix` guard: refuse `isCrossRepository`. Build the principal set from the PR author login and
   the author login of every commit on the PR (`gh api repos/{owner}/{repo}/pulls/<n>/commits`,
   `.author.login`). Resolve each login with `gh api
   repos/{owner}/{repo}/collaborators/<login>/permission`; `admin`, `maintain` and `write` pass.
   Fail closed: a commit with no linked GitHub login, a lookup error, a bot login, or any other
   permission refuses. A bot login can be allowed through the environment variable
   `FIXER_TRUSTED_LOGINS`. Merge commits from the base branch are covered because their authors
   are resolved like any other. Tests: a fork, a branch with one stranger commit among member
   commits, a commit with no linked login, a lookup failure, and an all-member branch.
4. Task D proof: tests that 5 cycles end in `ask`, `halt` leaves blocked and needs-human, and a
   comment never grants cycles.
5. Marker fields `model` and `tier`, `publish --model --tier`, readers tolerate them, and the
   `references/execution-profiles.md` section that says how the reviewer reports them. Old
   markers without the fields stay valid. `publish` also appends one JSON line (the same record
   `export-audit` emits) to `${XDG_STATE_HOME:-$HOME/.local/state}/pr-reviewer-fixer/audit.jsonl`;
   it is a convenience copy and never the evidence. Fields: `pr`, `pass`, `sha`, `verdict`,
   `critical`, `warning`, `note`, `model`, `tier`, `publisher`, `published_at`. If the file cannot
   be written, `publish` prints a warning and still succeeds, because the marker is the authority.
6. `export-audit <pr>` and `docs/compliance-records/README.md`. `export-audit` reuses the same
   marker-trust logic as `status` and the gate (allowlist, edited-comment check, fail closed on an
   empty or login-less allowlist) and refuses when the head moved after the last trusted marker,
   so a record never pairs one commit's verdict with another head.
7. Docs per the AGENTS.md table, CHANGELOG, bump to 0.3.0, run the loop on the PR.

Items already in the PR #2 debt block (`","` bypass, dead `ext` loop, run-together header sentence)
land in step 1 and in a cleanup commit.

## Success Criteria

- `bash tests/run-all.sh` passes with new cases for each of A, B, C and D.
- `REVIEW_MARKER_AUTHORS=","` and an unset allowlist make `status`, the gate and `budget` refuse.
- An edited marker comment is ignored by `status`, the gate and `export-audit`.
- `fix` on a fork PR, or on a branch with a commit by a non-member, exits non-zero before any
  label change.
- A PR with trusted markers can be exported into `docs/compliance-records/<pr>-<pass>.json`
  showing sha, counts, publisher and timestamps, plus the self-attested model id and tier.
- `export-audit` lists untrusted and edited markers under `ignored` with the reason and exports
  only trusted unedited ones. It refuses when no trusted marker remains, when the allowlist is
  empty or login-less, or when the head moved after the last trusted marker.
- A marker without `model` and `tier` is still accepted by `status` and the gate, and a reader
  that does not know the fields ignores them.
- No workflow, template, script or test names a provider key.
