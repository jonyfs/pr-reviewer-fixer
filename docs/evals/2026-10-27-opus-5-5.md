## Run 1, before the rule

recall 0.632 as scored (12/19) on the first run. 7 of 20 reports numbered lines from the `.patch`
file, not the new file. A simple line offset did not recover the defects, so this run is recorded
as scored and no corrected figure is claimed for it. The run-2 figure is the one to compare against.

## What the numbers say

- Detection: 19 of 19 in run 2. The reviewer finds the seeded defects across all ten OWASP Top
  10:2025 categories (A05 is the existing `sql-injection` case) and the five dimensions added in
  0.16.0: data integrity and migrations, reliability and resilience, scalability and capacity,
  operability and deployability, privacy and data protection.
- Precision: 0.32. The reviewer reports 2 to 5 CRITICAL or WARNING findings per case against one
  seeded defect, and the scorer counts every one that is not the seeded defect as a false
  positive. Some of them may be genuine issues in the sample code that the seeding did not plant;
  none of the 40 extra findings was classified by hand, so the figure is a floor on how noisy the
  reviewer is, not a measured false-positive rate.
- The line-number problem is in the skill prose: with a pasted diff nothing checks the anchor
  against git, so a wrong number passes through. 0.18.1 states the rule where a reviewer reads it.
  Run 2 has no anchor offset in its reports; they are committed under `run2/` (one file per case,
  named by case) with the scorer's output in `run2-score.txt`, so this can be re-checked. Its higher recall is not attributed to the rule alone:
  the two runs differ in shuffle order and sample, and only one run per condition was made.

## Limits

- 20 cases with 19 seeded defects, one per case, is a small sample and not a benchmark. Two runs of one
  model with one sample each do not give a variance. Run 1 reports were not committed.
- Model and date are recorded above; any change of model or skill prose needs a new run.
