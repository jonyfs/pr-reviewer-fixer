## Run 1, before the rule

recall 0.632 as scored (12/19) on the first run. 7 of 20 reports numbered lines from the `.patch`
file, not the new file. A simple line offset did not recover the defects, so this run is recorded
as scored and no corrected figure is claimed for it. The run-2 figure is the one to compare against.

## What the numbers say

- Detection: 19 of 19 in run 2. The reviewer finds the seeded defects across all ten OWASP
  categories and the five new dimensions.
- Precision: 0.32. The reviewer reports 2 to 5 CRITICAL or WARNING findings per case against one
  seeded defect. Several are real issues in the sample code that the seeding did not plant (missing
  error handling, unvalidated input), so the scorer counts them as false positives. These were not
  classified by hand.
- The line-number problem is in the skill prose: with a pasted diff nothing checks the anchor
  against git, so a wrong number passes through. 0.18.1 states the rule where a reviewer reads it.
  Run 2 has no anchor offset in its reports. Its higher recall is not attributed to the rule alone:
  the two runs differ in shuffle order and sample, and only one run per condition was made.

## Limits

- Three cases were a smoke test per tests/eval/README.md, not a benchmark. Two runs of one model
  with one sample each do not give a variance.
- Model and date are recorded above; any change of model or skill prose needs a new run.
