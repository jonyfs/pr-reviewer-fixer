# pr-fixer: 100 improvements

Research date: 2026-10-14. Scope: what the merged `pr-fixer` should add, given what already exists in
`pr-fixer` (lanes, cycles, push-race, head writability, flaky triage, ledger, config),
`pr-fixer` (falsify, threat-shaped red test, declared debt, 3 cycles, `review-cycle.sh fix`),
`specs/006-pr-skill-agents` (serialized write lanes, model and effort profiles, structured outcomes) and,
found while reading, the new `pr-reviewer` references (`trigger-and-handoff.md`, `report-contract.md`,
`execution-profiles.md`, `harness-matrix.md`). Items that would duplicate those files were dropped or
reworded to state only what is new.

Conventions. `Target`: SKILL (lean body, 25 items), reference (a `references/*.md` file), backlog
(needs tooling that does not exist). Source keys are full URLs that were opened in this session, or
`derived: <path>` for facts read from the repo, or `unverified` where the claim is modest and no page
confirmed it. Short names like [U14] point to the `Verified sources` section at the end.

## 3. Falsification and reproduction

| # | Improvement | Why (evidence) | Source | Target |
|---|---|---|---|---|
| 21 | Reproduction ladder, recorded per finding: (a) an existing failing test or CI log, (b) a reviewer-supplied command, (c) a generated failing test from the scenario, (d) a static call-path argument only. New: "reproduce" today has no ordered fallbacks and no record of which was used. | Bug-reproduction research shows the achievable rate is partial (about a third on Defects4J), so the skill needs an honest fallback rather than "cannot reproduce means refuse". | [U9]; [U8]; derived: .agents/skills/pr-fixer/SKILL.md (step 2) | SKILL |
| 22 | Reproduce at both the merge-base and the head. Fails on both: pre-existing, not introduced by this PR, declare as debt with owner. Fails only at head: introduced here. New: the base-versus-head test exists for CI checks only; extend it to review findings. | A hostile reviewer is "instructed to find a problem even when there is none"; pre-existing defects otherwise inflate the owed list and the diff. | derived: .agents/skills/pr-fixer/references/cycles-and-races.md (Flaky vs Real); derived: .agents/skills/pr-fixer/SKILL.md (step 2) | SKILL |
| 23 | Mechanically check that red is red for the right reason: classify the failing run as assertion failure versus error class (import error, collection error, fixture error, timeout, syntax error) and reject the error classes as "not red". | 24 | Run each reproduction test three times before the fix and three times after; require red three of three and green three of three. | 25 | Write the red test before the model reads the reviewer's `suggested_fix`: step one sees claim, scenario and code only; step two compares the test to the suggestion. | 28 | Time-box falsification per finding (N tool calls or minutes, configurable). | 29 | Match CI's environment before treating "does not reproduce" as evidence: read toolchain versions, container image, env flags and matrix entry from the failing workflow; when the environment cannot be matched locally, record the result as `unverified locally`, never as a refusal. | Refusal needs evidence that is itself valid; a different runtime version makes non-reproduction meaningless. | derived: .agents/skills/pr-fixer/references/cycles-and-races.md (Verify Before Push); unverified | reference |

## 4. Test-first discipline and proof

| # | Improvement | Why (evidence) | Source | Target |
|---|---|---|---|---|
| 31 | After the fix, generate a few differentiating inputs around the changed behaviour and compare pre-fix and post-fix outputs; any difference not named by the finding is flagged as a supplementary semantic change for review. A generator is the missing piece (a PatchDiff-style script). | 29.6% of plausible patches differed behaviourally from the reference patch, 28.6% of those were certainly incorrect, and faulty supplementary semantic changes caused 36.4% of the certainly incorrect ones. | [U6] | backlog |
| 32 | Characterization step for fixes touching shared code: before editing, pin current behaviour of the neighbouring untouched paths in a throwaway test, keep it green through the fix, discard it before commit. | "Plausible patches adapting more behavior than their oracle patches" were 27.3% of divergences in the same study. | [U6] | reference |
| 33 | Define "whole suite" operationally as the set returned by `gh pr checks --required`, mapped to local commands, and list in the report every required check with no local equivalent as "proved only in CI". New: the skills say "run the whole suite" and "narrowest relevant" without a derivation. | `gh pr checks --required` exists and exit code 8 separates pending; required checks are what the merge actually waits for. | [U31]; [U25] | reference |
| 34 | Make the closure report machine-checkable: per case `{command, exit_code, head_sha, tree_hash, tool_versions, output_sha256}` in a JSON block, plus a `proof-check` script that re-runs a sample and compares exit codes. Backs the rule "whoever repeats a proof runs it again". | An aggregate sentence was copied into a commit message as evidence although 1 of 8 mutations stayed green. | derived: .agents/skills/pr-fixer/SKILL.md (step 5) | backlog |
| 35 | Bind every proof to `git rev-parse HEAD^{tree}` and push only when the tree hash equals the proven tree. A rebase, merge or amend between proof and push changes the hash and forces a re-run. | Proof at a different tree is not proof; the existing rule re-verifies after a head move but does not say how to tell the tree changed. | derived: .agents/skills/pr-fixer/references/cycles-and-races.md | reference |
| 36 | Discover the test framework, location and naming from neighbouring tests and CI config; never introduce a new framework, assertion library or dependency to write the threat test. | Autofix "may suggest fabricated dependencies published under statistically probable names"; a new dependency for a test is the same failure by another route. | [U2]; [U16] (aider uses the project's own `--test-cmd`) | reference |
| 37 | Flake check for tests the fixer adds: run them five times, once in random order and once isolated; reject tests that depend on time, order, network or shared state. | Meta scores flakiness per test because flaky tests mislead engineers; a fixer that adds one makes the next cycle's checks unreliable. | [U7] | reference |
| 38 | Lint the test-file diff: flag any added `skip`, `xfail`, `.only`, `@pytest.mark.skip`, deleted assertion, loosened tolerance or widened expected set; such a hunk needs a finding that names it. | 39 | Reject fixes whose net effect is removing a guard, branch, validation or feature to make the test pass: flag diffs with deletions outweighing additions in the touched function, and require a stated reason. | Same overfitting pattern as item 38, on the source side. | [U6] | reference |
| 40 | Run the project's linter or type checker on each edited file immediately after each edit, before running tests, and feed the diagnostic back inside the same attempt. | Aider lints "any files which it edits" and retries on non-zero exit; Autofix reports syntactically invalid suggestions as a known failure, which a linter catches for free. | [U16]; [U2] | reference |

## 6. Conflicts, rebases and push-race safety

| # | Improvement | Why (evidence) | Source | Target |
|---|---|---|---|---|
| 51 | Resolve conflicts by merging the base into the head (a new merge commit), not by rebasing, and delete the `--force-with-lease` exception. The merged skill must never force-push, and a rebase of a pushed branch cannot be pushed without one. | `--force-with-lease` "interacts very badly" with background fetches and is "trivially defeated"; `--force-if-includes` only narrows it. A merge commit makes the push an ordinary fast-forward. | [U14]; derived: .agents/skills/pr-fixer/references/cycles-and-races.md | SKILL |
| 52 | Preview with `git merge-tree --write-tree <base> <head>` before touching the worktree: exit 0 clean, 1 conflicts, other means failure; parse the "Conflicted file info" section rather than scanning the tree. | 53 | Treat the server's rejection of a plain non-forced push as the authoritative race detector. Keep the fetch-and-compare as an early warning only. New: fetch then compare then push is a time-of-check to time-of-use gap; the remote enforces fast-forward at the instant of the push. | "git push refuses to update a remote ref that is not an ancestor of the local ref" unless forced. | [U14] | reference |
| 54 | Bot-owned branch rule: for Dependabot and Renovate heads, do not push. Dependabot stops rebasing once extra commits land, and a fixer commit silently freezes the bot's updates. | 55 | Enable `rerere.enabled` in the fixer's worktree so a conflict resolved in cycle 1 is reused identically in cycle 2, and review the recorded resolution with `git diff` (rerere does not stage). | Over multiple cycles and base advances the same hunk recurs; inconsistent re-resolution is a source of "fix that unfixes". | [U15] | reference |
| 56 | After any conflict resolution, validity is decided by the compiler, type checker and test suite, never by the model, and the report lists each resolved hunk with its choice (ours, theirs, combined) and a check that neither side's added lines were dropped. | An LLM judge accepted 4 of 5 resolutions that failed the deterministic structural check; models matched the developer on about 55% of true conflicts, so about 45% differ. | [U32] | reference |
| 57 | Numeric escalation thresholds from `merge-tree` output: more than K conflicted files, or the same function changed on both sides, or conflicts in files the fixer has not otherwise touched, escalate. | 58 | Poll `mergeable` on a timer at every cycle boundary, treating `UNKNOWN` as "retry after a delay", never as clean. ## Findings that change how the merged skill is shaped

1. A `pr-reviewer` skill already exists with trigger, handoff, findings block, severity arithmetic and
   per-harness profiles. `pr-fixer` should consume that contract and not restate it. The `pr-fixer`
   directory currently holds only copied `pr-fixer` references and the two scripts, with no `SKILL.md`.
2. The two source skills disagree on what blocks a merge (any blocking human comment versus only
   CRITICAL). Item 15 states the reconciliation; it needs an owner decision.
3. The "never force-push" requirement conflicts with the `--force-with-lease` exception in
   `pr-fixer/references/cycles-and-races.md`. Item 51 removes the exception by merging instead of rebasing.
4. Verified claims that are modest: Google's flaky test statistics could not be confirmed (page opened,
   body not extractable), so no Google number is used anywhere.
