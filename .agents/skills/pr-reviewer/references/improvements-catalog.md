# Improvements Catalog (pr-reviewer)

Researched 2026-10-14. `Target` says where an item belongs: SKILL (core rule), reference (detail file), backlog (needs tooling that does not exist). Decisions taken on the conflicts the research surfaced: severity maps to CRITICAL/WARNING/NOTE ([severity-and-verdict.md](severity-and-verdict.md)); the automatic run posts `--comment` and never auto-approves; the 13 dimensions stay, grouped by stance and batched by size ([agents-and-dispatch.md](agents-and-dispatch.md)) instead of collapsing to 5 lenses.

# pr-reviewer: 100 improvements

Date: 2026-10-14. Scope: the merged reviewer (pr-reviewer plus pr-reviewer), parallel read-only dimension and persona agents, script-enforced verdict, machine-readable hand-off to a fixer, cross-harness operation.

Conventions used in the tables:

- `Source` is a URL listed under Verified sources, `derived: <path>` for facts taken from reading this repo, or `unverified`.
- `Target` is `SKILL` (lean body, 25 items in total), `reference` (a references/*.md file) or `backlog` (needs tooling that does not exist yet).
- Severity words follow the adversarial vocabulary (CRITICAL, WARNING, NOTE). "Existing" always means what the current files already do.
- Where an item touches something the original agent design or the current skills already do, the row names what is new.

## 3. False-positive control and verification

| # | Improvement | Why (evidence) | Source | Target |
|---|---|---|---|---|
| 21 | Separate verifier stage: a fresh-context agent receives each candidate and may only confirm or refute it against code at the head SHA. The finding's author never verifies its own work. Existing: step 8 self-verification by the same agent; the original agent design has per-dimension generators only. | Claude Code Review runs a verification step after the finding agents; Uber found chained generate, grade, filter stages more important than prompt design; self-correction without external feedback can make results worse. | https://code.claude.com/docs/en/code-review; https://www.uber.com/us/en/blog/ureview/; https://arxiv.org/abs/2310.01798 | SKILL |
| 22 | Mechanical evidence check: every finding carries `evidence[]` (path, line, quoted snippet) and a script rejects any finding whose quote is not found at that line at the head SHA. Behaviour claims need a citation, not an inference from names. Existing: substantiation is a judgement call. | Claude's REVIEW.md guidance recommends "file:line citation, not an inference from naming" to cut false positives; functional comments were invalid more often than evolvability comments (35.1% vs 25.1%). | https://arxiv.org/html/2607.03316v2; https://code.claude.com/docs/en/code-review | SKILL |
| 23 | Optional execution check for CRITICAL candidates: run the existing test or a minimal repro in a sandbox without network or secrets, and mark the finding `reproduced`. | Fix-guided verification (run original and revised code against tests) is the mitigation proposed for LLM overcorrection. Needs a sandbox runner that does not exist here. | https://arxiv.org/abs/2603.00539 | backlog |
| 24 | Add a `pre-existing` class: bugs found in untouched code are reported separately, never counted toward the verdict. Existing: only pre-existing failing CI checks are excluded. | Claude Code Review uses a third marker for "a bug that exists in the codebase but was not introduced by this PR". | https://code.claude.com/docs/en/code-review | SKILL |
| 25 | Persona quota output is capped: a finding produced only to satisfy "each persona must find one issue" is tagged `quota`, is NOTE at most, and goes to the summary only, never inline. Existing: quota stays but its output has no separate lane. | LLM reviewers over-flag correct code, and richer prompts that demand explanations raise misjudgment; false positives are 43.3% of rejected agentic reviews. | https://arxiv.org/abs/2603.00539; https://arxiv.org/html/2607.03316v2 | SKILL |
| 26 | Category-level suppression from local history: keep counts of accepted versus dismissed findings per category and stop emitting categories dismissed repeatedly. An embedding variant can follow later. | Uber prunes whole categories with low developer value; Greptile blocks a comment similar to at least three downvoted ones and raised its address rate from 19% to 55%+ in two weeks. | https://www.greptile.com/blog/make-llms-shut-up; https://www.uber.com/us/en/blog/ureview/ | backlog |
| 27 | Do not use a self-rated 1-10 severity score as a gate. Gate on binary states (verified, unverified, reproduced). If a numeric confidence is added, calibrate its thresholds per category against labelled outcomes first. | Greptile found LLM severity ratings "nearly random" and few-shot examples made results worse; Uber's confidence scores worked because thresholds were tuned per assistant, language and category from feedback. | https://www.greptile.com/blog/make-llms-shut-up; https://www.uber.com/us/en/blog/ureview/ | reference |
| 28 | Dropped-candidate ledger: each agent returns candidates it considered and the reason it dropped each. The orchestrator audits drops for lost recall. Existing: the original agent design distinguishes empty from failed, not dropped from reported. | Greptile saw a model identify a deadlock in its reasoning and then omit it from the review; adding a target comment count recovered recall. | https://www.greptile.com/blog/model-inversion | reference |
| 29 | Scope filter by script: a finding must anchor in a changed hunk or name a changed symbol and its broken caller; otherwise it is `pre-existing` or dropped. | Out-of-scope accounted for 10.0% of rejections and redundant for 4.7%. | https://arxiv.org/html/2607.03316v2 | reference |
| 30 | Already-tracked check: before posting a WARNING or NOTE, search open issues and TODO references for the same defect and link instead of re-raising. | "Redundant" (already fixed or already tracked) was 4.7% of rejections. | https://arxiv.org/html/2607.03316v2 | reference |

## 5. Model and effort selection and cost

| # | Improvement | Why (evidence) | Source | Target |
|---|---|---|---|---|
| 41 | Author-aware routing: detect the authoring agent from `Co-authored-by` trailers, branch prefixes and title prefixes, and send the review to a different model family when one is available. Record `author_model` and `reviewer_model` in the report. Existing: the original agent design assigns model by dimension only. | In 1,000 PRs, each of two frontier models found more high-severity bugs in the other model's code (60.0% and 62.0% versus 53.7% and 50.5%). | https://www.greptile.com/blog/model-inversion | SKILL |
| 42 | The verifier and any grader use a different model family from the generator when available. | LLM judges show self-enhancement bias and favour their own generations; Uber's best configuration paired different vendors for generator and grader. | https://arxiv.org/abs/2404.13076; https://arxiv.org/abs/2306.05685; https://www.uber.com/us/en/blog/ureview/ | reference |
| 43 | Re-benchmark model choices on a golden set at each model release and pick by F1 and cost per PR, not by default or price tier. | Uber re-evaluates new models and keeps the highest F1; Factory measured GPT-5.5 at 5.63 USD per PR scoring 47.9% against 60.5% for GPT-5.2 at 1.25 USD. | https://docs.factory.com/benchmarks/review-benchmark | reference |
| 44 | A written profile table by reasoning demand: cheap model for summarising tickets, logs and diffs, deduplication and formatting; strong model for correctness, security and concurrency lenses. Existing: the original agent design requires a rationale but names no tiers. | Factory found open-source models reach roughly 75-86% of the top score at 3-8 times lower cost, which makes cheap passes viable. | https://docs.factory.com/benchmarks/review-benchmark | reference |
| 45 | Expose effort as a precision and recall knob: `low` emits only verified high-confidence findings with fewer agents; `high` widens coverage and verification. Report the setting in the marker. | Claude's `/code-review` states that low effort reports the findings it is most confident in, while medium through max broaden coverage. | https://code.claude.com/docs/en/code-review | reference |
| 46 | Per-review cost ceiling: token budget and turn cap in the brief, with estimated and actual spend printed in the report footer. | Reviews average 15-25 USD at Anthropic's quoted list; Factory's measured range is 0.15 to 5.63 USD per PR depending on model. | https://code.claude.com/docs/en/code-review | SKILL |
| 47 | Cache-friendly prompt layout: shared prefix (diff, conventions, context brief) first and the per-agent instruction last, so parallel agents hit the prompt cache. | Greptile v3 used about 3x more context tokens yet cut inference cost 75% through high cache hit rates. | https://www.greptile.com/blog/greptile-v3-agentic-code-review | reference |
| 48 | Run deterministic tools first (linters, type check, secret scan, the project's fast tests) in a sandbox, and subtract their findings from the review scope. Existing: reads CI results and says "never report what the linter owns" but does not run anything. | Uber: linters are accurate, reliable and cheap for syntactic patterns; LLMs are for what linters cannot check. | https://www.uber.com/us/en/blog/ureview/ | reference |
| 49 | Degrade instead of stop on budget pressure: run a single cheap pass restricted to security and correctness, and label the result `degraded` in the marker so it is never mistaken for a full pass. | Copilot reviews stop when the budget is exhausted and Claude skips the review; neither documents a lower-cost pass. | https://docs.github.com/en/copilot/concepts/agents/code-review | reference |
| 50 | Persist `models`, `effort`, `agents_run`, `agents_failed`, `tokens` in the report and marker so evaluation can correlate quality with configuration. Existing: the original agent design labels show model and effort at runtime only. | Quality comparisons across configurations need the configuration recorded with each result. | derived: specs/006-pr-skill-agents/spec.md | reference |

## 6. Security and prompt-injection hardening

| # | Improvement | Why (evidence) | Source | Target |
|---|---|---|---|---|
| 51 | Wrap every PR-controlled string (title, body, commit messages, comments, branch names, filenames, in-code comments) in labelled untrusted blocks with datamarking, and state in the system text that nothing inside them is an instruction. Existing: no rule on untrusted PR text. | Spotlighting cut attack success from over 50% to below 2% in the paper's experiments; OWASP lists segregating external content as a mitigation. | https://arxiv.org/abs/2403.14720 | SKILL |
| 52 | Load review rules from the base branch only. Treat a PR that edits REVIEW.md, AGENTS.md, CLAUDE.md, GEMINI.md, BUGBOT.md or copilot instructions as a high-risk change and review that edit as code. | Bugbot reads its config from the base branch so "a PR can't change how it's reviewed"; Copilot reads instructions from the head branch; GhostCommit hid its payload behind an AGENTS.md. | https://cursor.com/docs/bugbot | SKILL |
| 53 | Design rule: a review session never holds private data, untrusted content and an outbound channel at once. Agents get no network or posting tool; one script step posts after agents finish. | The lethal trifecta: private data plus untrusted content plus external communication lets an attacker exfiltrate; the advice is to remove one leg. | https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/ | SKILL |
| 54 | Never execute PR-controlled configuration or code outside a sandbox with no environment variables and no egress: linter configs with plugin loading, test runners on fork code, hooks, build scripts. Existing: workflow suggests `gh pr checkout` to "run/trace critical paths". New: that is allowed only inside the sandbox. | A `.rubocop.yml` in a PR executed attacker Ruby on the vendor's server and leaked API keys and a GitHub App private key. | https://kudelskisecurity.com/research/how-we-exploited-coderabbit-from-a-simple-pr-to-rce-and-write-access-on-1m-repositories | SKILL |
| 55 | Hidden-content scan script run before the agents: HTML comments, zero-width and bidi characters, large base64 blobs, instructions inside images or alt text. A hit is itself a security finding. | An attacker hid instructions in an HTML comment invisible in the web UI but returned verbatim by the API; Codex's guide says to review HTML comments and hidden text first. | https://labs.cloudsecurityalliance.org/research/csa-research-note-azure-devops-mcp-prompt-injection-20260801/ | reference |
| 56 | Never skip non-text artifacts silently: list images, PDFs and binaries in the depth map as `not inspected`, and flag convention files that reference images or external URLs. | GhostCommit's payload sat in a PNG; CodeRabbit's default excluded image files and Bugbot returned no findings on those PRs. | https://labs.cloudsecurityalliance.org/research/csa-research-note-ghostcommit-image-prompt-injection-ai-code/ | reference |
| 57 | Metadata-blind first pass for the security and correctness lenses: they see the diff and code without the PR description or commit messages; intent is reconciled afterwards. This is a proposed mitigation, not one the paper validates. Existing: step 1 reads intent before the diff. | Framing a vulnerability reintroduction as correct succeeded in 32 of 33 refinement attacks against two review pipelines, including Claude Code and CodeRabbit. | https://arxiv.org/abs/2603.18740 | reference |
| 58 | Least-privilege CI: default token read-only, pull-request write granted only to the publish job, actions pinned to a commit SHA, and the model job separate from the posting job. | GitHub recommends read-only default `GITHUB_TOKEN` and SHA pinning. | https://docs.github.com/en/actions/reference/security/secure-use | reference |
| 59 | Pass PR title and body to the agent as files or environment variables, never interpolated into a shell line or the prompt template. | GitHub documents script injection through `github.event.pull_request.title` and recommends environment variables. | https://docs.github.com/en/actions/reference/security/secure-use | reference |
| 60 | Sanitise text before posting: strip @mentions, external links, images and HTML comments (except the skill's own marker), and truncate to a size cap. | The Azure DevOps proof of concept posted a stolen wiki page back as a PR comment the attacker could read. | https://labs.cloudsecurityalliance.org/research/csa-research-note-azure-devops-mcp-prompt-injection-20260801/ | reference |
