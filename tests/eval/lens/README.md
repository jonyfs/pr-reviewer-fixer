# Per-lens seeded cases (catalog item 94)

Each review lens (one of the eighteen dimensions in `.agents/skills/pr-reviewer/references/dimensions.md`)
has up to 10 seeded defect cases. Each defect case `lens-<lens>-NN` has a clean twin
`lens-<lens>-NN-twin`: the same code with the single defect removed.

The reviewer must find the defect (its line, within tolerance, at or above `min_severity`) and must not
raise a CRITICAL or WARNING on the twin.

Layout is the same as `tests/eval/cases/`: `diff.patch`, `description.txt`, `expected.json`.

## What is checked here, and what is not

`cases/` is checked by `lens_check.py` (run by `tests/run-all.sh`), which needs no model. It confirms
that every defect sits on a line the diff adds, every twin has no defect, every defect has a twin, and
no lens has more than 10 defect cases.

It does not check that a reviewer finds the defects. That needs a real review run, which a person or a
harness session makes. The scorer in `tests/eval/score.py` reads `tests/eval/cases/` only, so these
cases are kept out of its recall figures. `tests/eval/lens_score.py` scores them per lens.

Run the structure check:

    python3 -I tests/eval/lens_check.py tests/eval/lens/cases

The cases were generated by sub-agents and have not been individually reviewed by a person. Each one is
a candidate until a person reads it, as the golden set's README requires.

## Scoring a review run

Produce one report per case in a directory (`<case>.md`, ending with the fenced `findings` block, as
`tests/eval/README.md` explains), then:

    python3 -I tests/eval/lens_score.py --reports DIR [--lens docs --lens privacy] [--min-recall 0.8] [--max-twin-fp 0.1]

For each lens it prints the recall (defects hit over defects seeded) and the share of clean twins on
which the reviewer reported a CRITICAL or WARNING. A NOTE can hit a NOTE-level defect (the
documentation and readability lenses seed NOTEs). `--lens` scores a subset, since running the
reviewer on all 360 cases is a lot of work. `lens_selftest.sh` tests the scorer on canned reports.
